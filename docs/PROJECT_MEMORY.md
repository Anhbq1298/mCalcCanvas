# Project memory — decisions and conventions

## Product decisions
- **Own canvas, not tldraw.** tldraw was replaced (licence/watermark constraints). Shapes are DOM elements in a transformed layer.
- **Google Docs look.** Menus, one toolbar with Math/Text formatting tabs that follow the selection, an Outline/Parameters panel on the left, a Properties panel on the right, white A4 pages.
- **Mathcad behaviour:**
  - Ordinary calculations run top to bottom, then left to right. Explicit unique `global(name,value)` definitions are visible throughout their worksheet; local definitions still override them below their position. See `docs/OPERATORS.md` for scope and numerical/symbolic operator limits.
  - `:` defines, `=` evaluates.
  - Mathcad keyboard shortcuts.
  - The red + insertion cross: Enter inserts a line and pushes content down; Backspace removes the blank line above the cross, Delete the blank line the cross is on (content below moves up).
  - Delete removes the selected regions and the lines they leave empty (content below moves up; a line still holding a label stays). One undo step.
- **Ruled-paper grid.** 20 px squares in light grey (no blue); major lines every 2 squares (40 px), drawn the same as the others. Math and text snap their *first baseline* onto a major line by default; Calculation → Snap: Squares changes this to 20 px. The math baseline is measured from the DOM (`props.baseline`, not persisted as authoritative).
- **No overlaps.** When a region would overlap an equation, the later region in reading order, and everything after it, moves down by whole lines (`layout.planSeparation`).
- **Inputs.** A definition from literals only (`fck := 35 MPa`, no variables) is an input: light-yellow highlight and blue text, on screen and in the PDF.
- **Changing an input's unit converts it.** Setting the unit of an input (toolbar or Properties) rewrites its literal with the same value (35 MPa → 5.07632… ksi, shortest exact decimal ≤ 12 digits); on other regions it only sets the result unit (`canvas/inputUnits.ts`, `engine.inputInUnit`).
- **Units display.** Light blue (`UNIT_COLOR`), with a `·` between number and unit (display only, `unitStyle.ts`). Temperatures keep `20 °C`.
- **Column templates** are generated by `tools/templates/gen_*.mjs` (see AGENTS.md §4); never edit their JSON by hand.
- **Templates.** The RC beam (EN 1992-1-1) template is the default on first visit; the steel beam is the test fixture. `?template=<id>` starts a new worksheet from a template.
- **Files.** `.mCCV` is the only worksheet and template extension (2026-11; it replaced `.mCalcCanvas`, and the separate JSON export was removed). The content is still the JSON document (internal serialization unchanged). Legacy `.mCalcCanvas` / `.json` files open silently and are converted, but the UI offers only `.mCCV`. Results are never stored.
- **File menu.** New · Open… · Recent · Save · Save As… (.mCCV) · Export PDF · Page setup… · Worksheet details. Save = browser now + version (+ the linked file after Save As); autosave is browser-only.
- **Save status.** Shown next to the title: Saved / Saving… / Unsaved changes / Not saved, and the linked file name with a dot while it is behind.
- **Annex.** Arrays and drawing data can live in an annex without breaking the top-to-bottom chain: each annex block is calculated at its link (▸ A.n) in the main body. One rule for users: "an annex is calculated at its link". Each block starts on a new page so blocks can be sorted by moving pages; numbers and page references are computed, not stored.
- **Input & Results.** A separate dense workspace, not a canvas table shape. Inputs and Outputs bind to exact region ids; units are inherited and cells hold numbers only. Only Calculate All runs the cases (worker pool, one worksheet set-up per worker, engine-level definition overrides, LaTeX never rewritten). Results are tied to the revision they were started from; any later change marks them outdated. Templates can ship a set-up (the rectangular column has 5 load cases). Print reports: a summary page of all cases, then the full worksheet for each case with its own input values and results (calculated only when printing).
- **Operators gallery.** It mirrors Mathcad Prime. Operators the engine can't evaluate yet are shown disabled, not hidden.

## Engineering policies
- Acceptance checks are strict (no tolerance).
- Intermediate values are never rounded.
- Absolute temperatures are affine.
- Error messages must be understandable to engineers.

## Conventions
- Test IDs (`data-testid`) are part of the test contract; keep them stable.
- `openFresh(page)` in e2e tests opens the steel-beam sample through `?template=steel-beam`.
- Single-file build for offline use: `npm run build:single`. When publishing it as an artifact, U+FFFD must be escaped.
- The deploy target is GitHub Pages (`gh-pages` branch) via CI after tests pass. The base path is relative (`base: './'`).

## Known limitations
- Kelvin values are linear; only °C is affine.
- A shape that crosses a page edge is clipped on its page when printed (a warning is shown first).
- There are no matrices or solvers yet (vectors, user functions, if blocks, graphs and annexes exist).
